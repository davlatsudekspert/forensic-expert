## 1. Usul

1. **Statik inventar** — `tool/lang_audit.py` ilova haqiqatda yuklaydigan fayllarni o‘qiydi
   (manba: `apps/mobile/assets/...`, ya’ni foydalanuvchi ko‘radigan nusxa):
   * `lib/core/l10n/arb/app_{uz,ru,en}.arb`;
   * `assets/content/pilot/content.db` (imzolangan paket, sxema v7) — 20 ta jadval/maydon guruhi;
   * `assets/content/guidelines/guidelines_v1.json` (23 karta, 76 test savoli, 107 adabiyot);
   * `assets/content/court_prep/court_prep_v1.json` (17 mavzu, 52 savol, 5 tamoyil, 8 simulyator, 58 adabiyot);
   * `lib/**/*.dart` — qattiq yozilgan UI literal’lar, `LocalizedText` xaritalari, davlat nomlari.
2. **Toifalash (A–G)** — har bir maydon uchun toifa kodda qat’iy belgilangan (2-bo‘lim).
   D/E/F/G asl matni **til tekshiruvidan o‘tkazilmaydi**; D/F tarjima qatlami esa maqsadli til
   sifatida tekshiriladi.
3. **Chizish yo‘li tahlili** — `lib/features/**` dagi `Locale('en')` va `['en']` fallback joylari.
4. **Real ilova** — Linux desktop (haqiqiy Flutter dvigateli, Xvfb), haqiqiy `bootstrap()`,
   haqiqiy imzolangan paket, tarmoq o‘chiq, akkaunt MOCK, Pro faqat test override. uz/ru/en
   uchun 23 tadan qadam; skrinshot + ekrandagi barcha matnlar (`screen_texts_*.json`) →
   detektor.
5. **O‘quv testi auditi** — `StudyCatalogBuilder` (Dart) mantig‘ining Python nusxasi
   (`quiz_audit()`), paket va kartalardan deterministik.

Hech qanday production backend, foydalanuvchi ma’lumoti yoki to‘lov ishlatilmadi.

### 10.2 Minimal kengaytma taklifi (sxema v8, faqat qo‘shimcha)

1. **Yangi jadval `localized_texts`** (manba takrorlanmaydi — faqat ID va xesh):
   ```
   target_type   TEXT  -- claim_excerpt | rule_excerpt | research_title_gloss | source_title_gloss
                       -- | screening_field | conflict_text | standard_note | context_text
                       -- | list_item | image_caption | instrument_title | authority_name | topic_body
   target_id     TEXT  -- masalan 'scr-immunoassay-opiates#analyte'
   lang          TEXT  -- uz | ru | en
   source_lang   TEXT  -- asl til (en, ru, uz)
   source_sha256 TEXT  -- asl matn xeshi (eskirish nazorati)
   text          TEXT
   status        TEXT  -- machine_draft | terminology_checked | claim_checked | reviewed | official
   claim_check_json TEXT  -- avtomatik: raqam/birlik/formula/foiz/cut-off ro‘yxati va moslik natijasi
   terminology_json TEXT  -- ishlatilgan glossariy termin ID’lari
   reviewer_id   TEXT NULL REFERENCES reviewers   -- faqat status='reviewed'
   reviewed_at   TEXT NULL
   content_version TEXT  -- shu til yozuvining versiyasi
   PRIMARY KEY (target_type, target_id, lang)
   CHECK (status <> 'reviewed' OR (reviewer_id IS NOT NULL AND reviewed_at IS NOT NULL))
   ```
   Mavjud `text_translations` (claim_excerpt/rule_excerpt) **o‘zgarmaydi** — eski kod o‘qishda davom
   etadi; yangi ilova ikkalasini birlashtiradi (yangi jadval ustun).
2. **Rasmiy hujjat nomlari:** court/guideline adabiyotiga (`references[]`) ixtiyoriy
   `titles: {uz, ru, en}` + `title_status: {uz: official|unofficial_translation, …}`;
   `jurisdictional_instruments.titles_json` da `_status` kaliti. Asl `title` saqlanadi.
3. **Karta/savol darajasi:** `translation_status` ga `TRANSLATED` va `REVIEWED` qiymatlari +
   `translation_review: {lang: {reviewer, reviewed_at, terminology_ok, claims_ok}}`
   (JSON, guidelines/court_prep — imzolanmagan asset, build.py/validate.py da tekshiriladi).
4. **Status ko‘tarilmaydi:** UI `reviewed` ni faqat `reviewer_id`+`reviewed_at` bo‘lsa ko‘rsatadi;
   validator (FE043 kengaytmasi) `reviewed` uchun `review_actions` (role=`translation`) yozuvini talab qiladi.
